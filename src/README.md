# 🏡 ניהול מעבר דירה

## 🌐 הכתובת החיה

**https://colorbull.github.io/afula-move/**

הקישור ציבורי וחינמי לחלוטין – נפתח מכל מכשיר, בלי התחברות ובלי התקנה.
כדאי לפתוח אותו בטלפון וללחוץ **"הוסף למסך הבית"** כדי לקבל אייקון כמו אפליקציה רגילה.

האתר מתארח ב־GitHub Pages מתוך המאגר https://github.com/ColorBull/afula-move
והוא מוגש כקובץ אחד: `index.html`.

### איך מעדכנים את האתר

הקובץ שבאוויר נבנה מקובצי המקור שבתיקייה הזו. אחרי שינוי בקוד:

```bash
python build_single.py
```

נוצר `index-single.html` – מעתיקים את כל תוכנו, נכנסים ל־
https://github.com/ColorBull/afula-move/edit/main/index.html
מדביקים במקום התוכן הקיים ולוחצים **Commit changes**. האתר מתעדכן תוך כדקה.

> אין צורך ב־git או בסיסמאות – העריכה נעשית ישירות בדפדפן.

אפליקציה לתכנון וניהול מעבר דירה. עברית מלאה, RTL, עובדת בטלפון ובמחשב,
עובדת גם בלי אינטרנט, ומסתנכרנת בין כל המכשירים דרך Google Firebase.

האפליקציה כללית ומשרתת כל מעבר – הכתובות ותאריך המעבר נקבעים במסך ההגדרות,
כך שאפשר להשתמש בה שוב בדירה הבאה.

## מה יש באפליקציה

התוכן בנוי לדירה ב**שכירות** ולהקמת **בית ראשון** – כלומר רוב הריהוט והציוד עדיין צריך להיקנות,
לא רק לעבור.

| לשונית | מה היא עושה |
|---|---|
| 🏠 **סקירה** | ספירה לאחור ליום המעבר, אחוזי התקדמות, התראה על פריטים שחייבים ליום הראשון, המשימות הקרובות וסיכום כספי |
| ✅ **משימות** | ~65 משימות מוכנות מראש, בשישה שלבים: חודשיים לפני → אחרי המעבר. כולל חוזה וביטחונות, מדידות לפני הזמנת רהיטים, ופרוטוקול מסירה |
| 🛒 **קניות** | רשימת קניות לבית ראשון (~57 פריטים) לפי אזור בדירה, עם עדיפות **ליום הראשון / שבוע ראשון / בהמשך**, מחיר משוער מול מה ששולם בפועל, וחנות |
| 📦 **ארגזים** | רשימת ארגזים ממוספרת: תוכן, חדר מקור ← חדר יעד, סטטוס, סימון "שביר", חיפוש וסינון, והדפסת תוויות להדבקה |
| 💰 **תקציב** | טבלת הוצאות המעבר: מתוכנן מול בפועל, סימון "שולם", וסיכום חריגה/יתרה |
| 🔌 **שירותים** | העברת חשמל, מים, ארנונה, גז, אינטרנט, דואר, משרד הפנים, קופת חולים ועוד – עם סטטוס, מספר לקוח וכפתור חיוג |
| 📄 **מסמכים** | קריאות מונים, חוזה, פרוטוקול מסירה וקבלות – עם קישור לתמונה בגוגל דרייב |
| 📇 **אנשי קשר** | משכיר, מובילים, מרכיב רהיטים, טכנאי מזגנים – עם חיוג ישיר ווואטסאפ |

⚙️ בהגדרות: תאריך המעבר, כתובות, סנכרון ענן, ייצוא/ייבוא גיבוי, ואיפוס.

### ניווט, חיפוש וסינון

* **תפריט צד** – כפתור ☰ בפינה הימנית העליונה פותח וסוגר תפריט נשלף עם כל המסכים,
  ולצד כל מסך מוצג מספר הפריטים שעדיין פתוחים. נסגר בלחיצה על מסך, על הרקע או ב-Esc.
* **חיפוש** – שורת החיפוש שמתחת לכותרת מסננת את המסך שבו נמצאים כרגע.
  במסך **סקירה** היא הופכת לחיפוש-על שמציג תוצאות מכל הקטגוריות יחד, מקובצות לפי מסך.
* **סינון משימות** – במסך המשימות אפשר לסנן לפי שלב (חודשיים לפני, חודש לפני,
  שבועיים, שבוע, יום המעבר, אחרי המעבר) ולפי בוצע / לא בוצע.

### איך עובדת לשונית המסמכים

היא **לא** מאחסנת קבצים – היא מרכזת רשומות. הזרימה: מצלמים בטלפון (מונה חשמל, מצב הדירה, קבלה) →
התמונה עולה ממילא לגוגל תמונות / גוגל דרייב → מעתיקים משם קישור שיתוף ומדביקים ברשומה.
כך המספר החשוב והצילום נמצאים יחד, וזמינים מכל מכשיר. יש כפתור **🔗 פתח קישור** בכל רשומה.

## הפעלה מהירה (בלי שום התקנה)

פותחים את `index.html` בדפדפן (לחיצה כפולה). הכול נשמר בזיכרון הדפדפן של אותו מכשיר.
זה מספיק כדי להתחיל לעבוד כבר עכשיו — אבל **בלי סנכרון בין מכשירים**.

להרצה כשרת מקומי (למשל כדי לבדוק את מצב האפליקציה כמו בטלפון), מתוך תיקיית `afula-move`:

```bash
python -m http.server 5178
```

ואז פותחים http://localhost:5178

## סנכרון בין המכשירים

הכול כבר מוגדר – אין מה להתקין ואין מה להדביק.

1. פותחים את https://colorbull.github.io/afula-move/
2. נכנסים ל־⚙️ **הגדרות** ← **סנכרון בין מכשירים**
3. לוחצים **התחברות עם Google** ובוחרים את החשבון

מרגע זה הסמן למעלה מציג **● מסונכרן**, וכל שינוי נשמר בענן ומופיע מיד
בכל מכשיר אחר שמחובר לאותו חשבון Google. חוזרים על אותם שלושה צעדים בטלפון,
ורואים שם בדיוק את אותו לוח תכנון.

בלי התחברות האפליקציה עדיין עובדת במלואה – פשוט שומרת רק במכשיר הנוכחי.

### איך זה בנוי

| | |
|---|---|
| פרויקט Firebase | `afula-move` (תוכנית Spark – ללא עלות) |
| מסד נתונים | Cloud Firestore, אזור `eur3` (אירופה) |
| התחברות | Google בלבד |
| מיקום הנתונים | מסמך יחיד בנתיב `moves/{uid}` |

**על האבטחה:** כללי האבטחה (`firestore.rules`) מתירים גישה למסמך רק למשתמש
שה־uid שלו זהה לשם המסמך. כלומר כל חשבון Google מגיע אך ורק לנתונים של עצמו,
וגולש לא מחובר לא מקבל שום גישה.

מפתח ה־API של Firebase מופיע בקוד הגלוי – **וזה תקין**. בניגוד לסיסמה, מפתח
צד־לקוח של Firebase נועד להיות פומבי; הוא רק מזהה את הפרויקט. מה שמגן על
הנתונים הוא כללי האבטחה ורשימת הדומיינים המורשים, ולא הסתרת המפתח.

## 🔐 על מפתח ה-API והתראות של GitHub

GitHub שולח לפעמים התראה על "Google API Key" שנמצא ב-`index.html`. **זו אינה
דליפה, ואין צורך להחליף את המפתח.**

מפתח ה-API של Firebase בצד הלקוח נועד להיות גלוי. הוא נשלח לכל דפדפן שנכנס
לאתר, ואפשר לראות אותו בלחיצה על "הצג מקור" – בין אם הקוד נמצא ב-GitHub ובין
אם לא. הוא רק מזהה את הפרויקט; הוא לא נותן גישה לשום דבר בפני עצמו.

GitHub מסמן אותו כי הקידומת `AIza` משותפת גם למפתחות גוגל שכן רגישים
(מפתחות שרת, מפתחות Maps עם חיוב), והסורק לא יכול להבחין ביניהם.

**מה באמת מגן על הנתונים:**

1. **כללי האבטחה** (`firestore.rules`) – כל משתמש מגיע רק למסמך ששייך לו:
   `request.auth.uid == uid`. בלי התחברות אין שום גישה, וגם עם המפתח ביד
   אי-אפשר לקרוא נתונים של מישהו אחר.
2. **רשימת הדומיינים המורשים** ב-Firebase Authentication – התחברות אפשרית
   רק מ-`colorbull.github.io`.

**מה כן סוד ואסור שיגיע לגיט:** קובץ `mcp-server/service-account.json`.
הוא נמצא ב-`.gitignore` ומעולם לא נכנס למאגר.

### לסגור את ההתראה ב-GitHub

נכנסים ל-Security ← Secret scanning, פותחים את ההתראה ובוחרים
**Close as → Used in tests** או **False positive**.

### חיזוק אופציונלי (מומלץ)

אפשר להגביל את המפתח כך שיעבוד רק מהאתר שלכם ורק מול השירותים הדרושים:
Google Cloud Console ← APIs & Services ← Credentials ← המפתח של הדפדפן:

* **Application restrictions** ← HTTP referrers, ומוסיפים:
  `colorbull.github.io/*` , `afula-move.firebaseapp.com/*` , `localhost/*`
* **API restrictions** ← Restrict key, ומסמנים:
  Identity Toolkit API, Token Service API, Cloud Firestore API,
  Firebase Installations API

חשוב לבדוק את האתר אחרי השינוי – הגבלה חסרה עלולה לשבור את ההתחברות.

## הערות

* מספרי הטלפון בלשונית "שירותים" הם ברירת מחדל לנוחות בלבד — כדאי לאמת מול הספק הרלוונטי. כל שדה ניתן לעריכה.
* סכומי הקניות בלשונית "קניות" נספרים בנפרד מלשונית "תקציב" כדי שלא ייספרו פעמיים. המסך "סקירה" מציג את הסכום המשולב.
* בפתיחה ישירה של הקובץ מהמחשב (`file://`) הסנכרון מושבת בכוונה — הדפדפן חוסם אותו. הכול עדיין נשמר מקומית.
* הנתונים נשמרים כמסמך אחד ב־Firestore בנתיב `moves/{קוד המרחב}`. עדכון מנצח = האחרון ששמר.
